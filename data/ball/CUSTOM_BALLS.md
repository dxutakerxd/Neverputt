# Custom Balls Guide

How to create custom ball skins for Neverball and Neverputt. Both games share the same ball engine — a ball created here works in either game.

## Directory Structure

Each ball lives in its own subdirectory under `data/ball/`. The game auto-discovers balls at runtime by scanning for subdirectories containing at least one of three `.sol` files. No registration file needs to be edited.

A minimal ball directory:

```
data/ball/<name>/
  <name>                    # Material file (no extension)
  <name>.png                # Texture (512x256 equirectangular)
  <name>-solid.map          # Geometry definition
  <name>-solid.sol          # Compiled binary (generated by mapc)
```

The directory name must match the base filename throughout. The engine discovers balls by checking for `<name>-solid.sol`, `<name>-inner.sol`, or `<name>-outer.sol` inside each `ball/` subdirectory (see `ball/st_ball.c:has_ball_sols()`).

## Three-Layer Rendering System

Each ball can have up to three independently rendered layers. Only one is required (typically `solid`).

| Layer | File suffix | Behavior |
|-------|------------|----------|
| **solid** | `-solid.sol` | Rotates with ball physics. Main visible surface. |
| **inner** | `-inner.sol` | Drawn inside the solid layer. Optionally uses pendulum mode (gravity-oriented). Used for glowing cores, internal effects. |
| **outer** | `-outer.sol` | Drawn outside the solid layer. Optionally uses pendulum mode. Used for rings, shells, atmosphere. |

See `share/ball.c:ball_init()` for how layers are loaded. Missing layers are handled gracefully.

## File Reference

### Texture (`<name>.png` or `<name>.jpg`)

- **Dimensions:** Must be power-of-two. Standard size is **512x256** (2:1 aspect ratio).
- **Format:** PNG (RGB or RGBA) or JPEG.
- **UV mapping:** Equirectangular projection matching the standard sphere model `ball/basic-ball/basic-ball.obj`.
- Other sizes found in existing balls: 256x256, 256x128, 128x128, 64x64 (for detail/billboard textures on multi-layer balls).

### Material file (`<name>`, no extension)

Plain text file defining rendering properties. Must share the same base name as the texture.

```
diffuse   0.8 0.8 0.8 1.0
ambient   0.2 0.2 0.2 1.0
specular  1.0 1.0 1.0 1.0
emissive  0.0 0.0 0.0 1.0
shininess 90.0
flags     lit
angle     45.0
```

**Properties:**

| Property | Values | Description |
|----------|--------|-------------|
| `diffuse` | R G B A | Base color from directional light. A controls alpha transparency. |
| `ambient` | R G B A | Color contribution from ambient light. |
| `specular` | R G B A | Highlight/reflection color. |
| `emissive` | R G B A | Self-illumination. Set to `1.0 1.0 1.0 1.0` for glowing effects (e.g. lava). |
| `shininess` | 0.0 - 128.0 | Tightness of specular highlight. Higher = tighter/shinier. |
| `flags` | space-separated | See flag list below. |
| `angle` | degrees | Crease angle for smooth shading between faces. |
| `alpha-test` | e.g. `gequal 0.01` | Optional pixel transparency filter. |

**Flags:** `lit`, `transparent`, `additive`, `clamp-s`, `clamp-t`, `decal`, `environment`, `reflective`, `shadowed`, `two-sided`, `particle`

### Map file (`<name>-solid.map`)

Quake/Radiant-style entity format defining the ball geometry.

**Simple ball** (reuses the standard sphere model):

```
{
"classname" "worldspawn"
"drawback" "1"
"depthmask" "1"
}
{
"classname" "misc_model"
"material" "ball/<name>/<name>"
"model" "ball/basic-ball/basic-ball.obj"
}
```

**Worldspawn keys** (rendering flags for the layer):

| Key | Value | Description |
|-----|-------|-------------|
| `drawback` | `1` | Draw back faces first (transparency sorting via face culling) |
| `drawclip` | `1` | Sort transparency via clip planes |
| `depthmask` | `1` | Enable depth buffer writing |
| `depthtest` | `0` | Disable depth testing (for glow effects) |
| `pendulum` | `1` | Use gravity-oriented rotation (for inner/outer layers) |

**Entity types:**

- `misc_model` — References a 3D OBJ model. Keys: `model` (path to `.obj`), `material` (path to material file).
- `info_null` — Defines a billboard/sprite. Keys: `image`, `origin`, `height`, `width`, `time`, `xrot`/`yrot`/`zrot`, `flag`.

### OBJ model

Most balls reuse `ball/basic-ball/basic-ball.obj` — a tessellated sphere with equirectangular UV mapping. Custom OBJ models must use triangular tessellation with normals and texture coordinates.

### SOL binary (`<name>-solid.sol`)

Compiled from the `.map` file using `mapc`. This is the file the game actually loads at runtime.

## Compilation

The `mapc` tool compiles `.map` files to `.sol` binary format:

```bash
# Single ball
./mapc data/ball/<name>/<name>-solid.map data

# All maps in the project
make sols
```

### Building mapc

`mapc` is built from the desktop Makefile. Required dependencies: `libpng-dev`, `libjpeg-dev`, `libsdl2-dev`.

```bash
# Install dependencies (Ubuntu/Debian)
sudo apt-get install -y libpng-dev libjpeg-dev libsdl2-dev

# Build mapc only
make mapc ENABLE_NLS=0
```

Note: The Makefile's `MAPC_LIBS` doesn't include `-lSDL2` but `solid_base.c` uses `SDL_Log`. If linking fails with undefined `SDL_Log` references, manually add `-lSDL2` to the link command.

## Ball Selection

- **Neverball** has a ball selection screen (`ball/st_ball.c`) accessible from the options menu.
- **Neverputt** has no ball selection UI. It uses whatever `ball_file` is set in the config (defaults to `basic-ball`). The config key is `CONFIG_BALL_FILE` with value format `ball/<name>/<name>`.

## Step-by-Step: Creating a New Ball

1. Create directory: `data/ball/myball/`
2. Create texture: `data/ball/myball/myball.png` (512x256, power-of-two, equirectangular)
3. Create material: `data/ball/myball/myball` (no extension, see template above)
4. Create map: `data/ball/myball/myball-solid.map` (see template above)
5. Compile: `./mapc data/ball/myball/myball-solid.map data`
6. The ball is auto-discovered. No registration needed.

## Existing Ball Complexity Examples

**Simple** (solid layer only, reuses basic-ball.obj): melon, magic-eightball, basic-ball, diagonal-ball, cheese-ball

**Medium** (solid + inner or outer): earth, lava, eyeball, blinky

**Complex** (multiple layers, custom OBJs, billboards): atom, reactor, catseye, snowglobe, ufo, sootsprite, saturn

Inspect any existing ball directory under `data/ball/` for working examples.
